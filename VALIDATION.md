# Validation evidence — 2026-10-22

Local platform: macOS darwin/arm64, Apple M2, Go 1.27.1. No external
services or model APIs are involved in simulation or tests.

## Observed checks

- `go test -count=1 -cover ./...`: all packages passed; statement coverage
  `cmd/dst` 88.0%, `examples/counter` 88.0%, `sim` 89.0%.
- `go test -race -count=1 ./...`: all three packages passed.
- `go vet ./...`, formatting and `git diff --check`: passed.
- `./scripts/smoke.sh`: built CLI, found failure seed 1, generated byte-identical
  recordings in separate processes, replayed the new and committed failure traces,
  searched fixed seeds 1–1000 with partition ticks 2–35, and replayed a success.
- `go test ./sim -run '^$' -fuzz FuzzDeterminism -fuzztime=5s -parallel=2`:
  passed, 8,405 executions in about 5 seconds, no failure. Two initial corpus
  entries plus 74 newly interesting inputs; these are local observations and fuzz
  counts will vary across runs.
- Counter tests: 95/100 broken seeds (1–100) exhibited lost updates; all 1,000
  fixed seeds (0–999) passed with partition 2–35. The additional fault matrix
  covered 4 max delays × 4 healing times × 50 seeds = 800 passing cases.

The seed-1 counterexample (ticks):

| Tick | Evidence |
| --- | --- |
| 6, 8 | Server receives both reads while value is 0 |
| 10, 11 | Clients receive `value:0` and independently compute 1 |
| 13, 14 | First client's write and retry set server to 1 |
| 16, 17 | Second client's write and retry also set server to 1 |
| 23 | Both clients have acknowledgements; invariant rejects value 1 |

The recording contains 15 events and pending work at the failure. The fixed
protocol performs an increment once per client ID at the server, including under
request retries; it assumes this server and its deduplication state remain alive.

## Reproducible microbenchmark

```sh
go test ./examples/counter -run '^$' -bench BenchmarkFixedCounter -benchmem -benchtime=1s -count=3
```

Observed ns/op: 277,506; 193,493; 263,000. Allocations: 277/op; memory:
16,924–16,931 B/op. Each operation constructs a seeded fixed-counter simulation,
runs it and collects per-event snapshots. Seeds vary by iteration; event counts
can differ. Other build checks were active during measurement, so these are noisy
local measurements, not a controlled throughput comparison or portability claim.

## Remote validation

The workflow tests Go 1.23.x and stable on Linux and macOS. Remote results must be
checked against the pushed commit in [GitHub Actions](https://github.com/Soumil-Makhija/deterministic-simulation-tester/actions).
The dated daily run report records the actual verified run status and commit;
this document does not predeclare a remote outcome.

Workflow action usage was checked against the official
[checkout](https://github.com/actions/checkout) and
[setup-go](https://github.com/actions/setup-go) documentation.

## Boundaries

A bounded seed search is evidence about the tested model only. It does not prove
correctness, sample a known distribution of real failures, or test an actual
production service. See README for deterministic-model obligations, link/timer
semantics, finite horizons and unsupported crash/disk behavior.
